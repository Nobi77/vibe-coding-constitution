# Docs 文件夹规范

`Docs/` 是产品的事实区：只描述「产品是什么」，不描述「这一次要改什么」（那是 specs 的事），不放代码。

## 标准文件清单（按需裁剪，裁剪须在本文件注明）

| 文件 | 职责（唯一） |
|---|---|
| `00-overview.md` | 产品总览：一句话定位、目标用户、核心价值、功能地图 |
| `01-architecture.md` | 架构：模块划分、模块间关系、运行环境、部署方式 |
| `02-data-model.md` | 数据模型：实体、字段、关系、存储位置（无持久数据时写明「无」） |
| `03-interfaces.md` | 接口约定：对外 API / 命令行 / 文件格式的输入输出 |
| `04-business-rules.md` | 业务规则：判定逻辑、额度、例外与边界 |
| `05-permissions-and-security.md` | 权限与安全：谁能做什么、密钥与隐私的处理方式 |
| `99-decisions.md` | 决策记录：重大选择及其理由（只追加，不改旧条目） |

## 项目分级与必备文档（唯一出处）

| 分级 | 判定 | 必备事实文档 |
|---|---|---|
| L1 小型脚本 | 单文件或少量文件、一次性 / 低频工具、无对外服务 | 只需 `00-overview.md`（定位、输入输出、数据说明、运行方式合一） |
| L2 中型工具 | 多模块、长期复用的 CLI / 自动化任务 | `00-overview.md`、`01-architecture.md`、`02-data-model.md`（无数据在总览注明） |
| L3 正式产品 | 对外服务、商业化、涉及用户数据 | 下方标准清单全量（00–05＋99） |

其他文件（宪法、Agent 规程、提示词）引用必备数量时一律指向本表，不另写数字。

## 写作规则

1. 一份文件一个主题；同一事实只定义一次，其他文件用相对链接引用。
2. 每份文件头部写：职责一句话、最后核对日期、来源依据。
3. 未确认的信息标注「未确认」，并写明待核对的方式。
4. 修改事实后，在该文件末尾「变更记录」追加一行：日期｜改动｜依据（SPEC 编号或用户决定）。
5. 文件名用两位序号前缀排序，新增主题顺延编号，不复用已删除的编号。

## 模板

`Docs/_template-fact-doc.md` 是单份事实文档的空白模板，新建事实文档从它复制。
