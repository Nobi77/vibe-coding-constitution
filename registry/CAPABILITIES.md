# 能力登记册

已沉淀、可被其他 Muse 账号 / Agent 复用的能力在此登记。登记的目的是：任何账号接到任务时，先查本表有没有现成能力可调用，不重复造轮子。

| 能力名 | 用途 | 存放位置 | 调用方式 | 验证状态 |
|---|---|---|---|---|
| Vibe Coding 约束体系 | 约束全部 AI 编程工作：文档分离、SPEC 驱动、多 Agent 分工、Git 门禁 | 本仓 `CONSTITUTION.md` | 读宪法＋按角色读 `agents/`；新账号用 `prompts/bootstrap-prompt.md` 启动 | 已实测（2026-11-24，证据：本仓已推送 GitHub 并回读验证 24 个文件齐全；外部审核记录见 `notes/`） |

## 登记格式（新增能力照此填）

- **能力名**：唯一名称，不与已有重名。
- **用途**：一句话说清解决什么问题、适用什么场景。
- **存放位置**：仓库＋文件路径，必须是可直接打开的精确路径。
- **调用方式**：怎么触发 / 读取顺序 / 需要的输入，写到新账号照着就能用的程度。
- **验证状态**：未验证 / 已实测（附日期与证据位置）。未实测的不许写成已验证。

## 规则

1. 能力只有沉淀成文件并登记到本表，才算「可被其他账号调用」；只存在于某次对话里的不算。
2. 能力内容变更后同步更新本表对应行与验证状态。
3. 涉及密钥的能力只登记调用方式，密钥本身永不进仓（见宪法第八章）。
