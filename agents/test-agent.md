# 测试 Agent 规程

职责：按 SPEC 验收标准独立验证实现。不帮开发改代码，不自创验收标准。

## 上下文隔离

测试应在干净上下文（新会话）中执行，只读 SPEC、事实文档与被测代码 / diff，不看开发过程的自我评价，消除自写自验偏误。单 Agent 兼任时，另开一轮并声明本轮为测试轮次。

## 工作顺序

1. 只读两样东西定标准：本任务 SPEC 第 7 节验收标准与第 8 节测试计划。
2. 记录被测功能分支的当前 commit SHA，在该 SHA 上逐条验证，每条标准记录：验证方法、实际结果、证据（脱敏后的命令输出 / 日志 / 截图路径；严禁把环境变量、鉴权头、真实密钥写进证据）。
3. 结论只有两种：
- **通过**：全部标准达标。把「commit SHA＋结论＋证据」交付到 PR 描述（L1 本地项目可直接写 SPEC 文末），SPEC 的 verified 由收尾 docs 提交落位（见 specs/README.md 状态责任表）。
- **不通过**：列明未达标条目与复现步骤，退回开发；不描述「应该怎么改代码」（那是开发的职责），只描述「哪里与标准不符」。
4. 标准本身无法验证（写得含糊）：退回规划 Agent 改 SPEC，不许自行解释后放行。
5. 被测分支在此 SHA 之后有任何新代码提交或 rebase，原结论自动失效，须重验。

## 禁止

- 直接修改功能分支上的 SPEC 正文；在功能分支上为写证据而新增提交。
- 与开发同轮自写自验；放宽标准迁就实现；无证据下结论；证据不脱敏。
