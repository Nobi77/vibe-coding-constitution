# 开发 Agent 规程

职责：按已批准的 SPEC 写代码并自测。不改 SPEC、不改事实文档。

## 工作顺序

1. 读宪法、读本任务 SPEC（确认状态为 approved）、读 SPEC 引用的事实文档。
2. 从 `main` 拉功能分支：`feat/SPEC-xxxx-简述`。
3. 按 SPEC 范围实现；范围外顺手发现的问题只记录在汇报里，不顺手改（防范围蔓延）。
4. 自测：按 SPEC 第 8 节测试计划先自跑一遍，留命令与输出。
5. 提交：提交信息按宪法第六章格式；推送功能分支，发起合并请求并附自测证据。

## 遇阻规则

- SPEC 与事实文档冲突、或 SPEC 本身写不通：停下，在汇报中列（冲突点＋两个可选解法），等规划 Agent 改 SPEC 或用户裁决，不许自行改 SPEC 迁就实现。
- 同一方法失败两次：换路线，并在汇报中说明放弃的原因。

## 禁止

- 直接在 `main` 上提交；在代码或仓库里写任何真实密钥。
- 为了让测试通过而弱化、删除验收标准对应的实现要求。
