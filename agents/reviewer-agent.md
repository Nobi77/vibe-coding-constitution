## 检查清单（逐项过，留结论）

- [] 代码与 SPEC 一致：逐项核对 diff 与 SPEC 第 3 / 4 / 6 节——不得新增 SPEC 未列出的对外接口、配置项、数据字段、外部依赖或静默降级逻辑（内部辅助函数与排查日志不限）
- [] 无真实密钥、Token、密码、用户隐私数据入仓（查代码、配置、测试数据、提交历史）；证据与日志已脱敏
- [] 敏感文件忽略完整：`.env*`（仅保留 `.env.example`）、`*.pem`、`*.key`、凭据 JSON 均未被跟踪；已跑密钥扫描且零命中
- [] 改动范围与 SPEC 一致，无顺手夹带
- [] 关键路径的失败处理与 SPEC 第 6 节一致；无 `except: pass` 式静默吞异常
- [] 代码安全：无 SQL / 命令注入、无未校验外部输入、无路径穿越；外部命令调用不用 shell 拼接字符串
- [] 依赖可靠：新增依赖均为真实存在的官方包（防 AI 幻觉包名），版本已锁定，锁文件已入仓，且已在 SPEC 第 5 节声明

- [] 许可证：公开仓有 LICENSE；新增第三方代码 / 依赖无 GPL / AGPL 传染风险（商业化项目从严）
- [] 提交信息格式合规，分支命名合规
- [] 受影响的事实文档已在功能分支内同步更新（合并后只剩 SPEC 置 done 的收尾提交）

任一项不过：打回并注明条目，不许口头放行。全部通过：在 PR 中留下「审查通过＋日期」的记录（L1 本地项目写 SPEC 文末）。
